# 真人试玩与 #26 验收

先用已部署的在线版或 `cd game; npm ci; npm run dev` 开始新浏览器会话。正式数据需要一次自然流程；T 切年龄、R 手动复活和控制台改变角色/怪物状态均不用于平衡结论。正常战死和检查点重生可以保留，它们本来就是游戏难度的一部分。

每次试玩记录游戏版本、操作者代号、预先选择的打法（偏格挡反击 / 偏移动进攻）、是否从第一关开始、实际完成/放弃原因，以及三关的主观反馈。先取得至少两种打法各一次的可解释样本，再决定是否增加样本；这种小样本只能发现明显问题，不能声称胜率相同。

结局后，在浏览器开发者工具 Console 输入：

```js
__fmnTelemetry.downloadAll()
```

下载的 `ute-playtests-*.json` 包含此浏览器保存过的各关记录和当前关快照，按 runId 去重；不需要在过场中赶着导出。它只读取本游戏的 `fmn-telemetry-` 键。`warnings` 若提示存储不可用，则文件只有当前关，不能按三关完整样本处理。旧版无 runId 的记录会提示跳过。多次试玩可能在同一文件，按 startedAt/runId 和操作者备注分组；不要混入自动化样本。

字段口径：

- `revision` 为构建源码SHA；源码归档无Git时可能为unknown，需手工记录发布版本。
- `outcome=completed` 是收到关卡结算事件，`interrupted` 为退出/切关中断。中断不应偷偷算通关或失败胜率。
- `elapsedMs` 是包含阅读、暂停和闲置的墙钟时长；它不是纯战斗时长。需要备注长时间离席。
- `keyPresses` 是有效游玩期间不含repeat的物理按下次数；长按持续施法和格挡时长无法由此反推，不可自动据此给玩家贴打法标签。
- `contamination` 含调试切关、手动复活、异常悬浮或主动标记时，要单独分析。外部控制台注入无法自动全部识别。

验收表仍待真人填写：每关8–15分钟是否达成、两种打法在同版本相似水平玩家中的完成/尝试分子分母、老年持续施法的手感与场面密度。当前自动探针没有提供任何真人通关样本。1600像素地图的无阻碍步行仅约17–21秒，不能据此证明8–15分钟，也不应为凑时长先机械拉长地图。
